# Modern Redesign

Методологія сучасного редизайну існуючого UI без переписування з нуля.
Мета — підняти візуальну якість і UX, зберігши бренд, дані й робочий функціонал.

## 0. Спершу — дослідити, не малювати

Перед будь-якою правкою стилю:

1. **Знайди джерело правди по токенах.** Кольори, шрифти, breakpoint-и, міксини
   (у цьому проєкті: `dev/styles/utils/variables/`, `dev/styles/utils/mixins.scss`).
   Редизайн має використовувати наявні змінні, а не хардкодити нові кольори.

   **Брендові токени цього проєкту** (`css-vars.scss`) — актуальна палітра й план
   міграції зі старої бордової описані в [`REDESIGN.md`](../../../REDESIGN.md):
   ```
   --brand-green-700  основний бренд (лого)   → аліас --bg (легасі, ~30 місць)
   --brand-green-900  глибокий фон (футер)
   --brand-gold-400   акцент — ТІЛЬКИ на зеленому/темному
   --brand-gold-600   золото для бордерів/іконок на світлому
   --brand-sand-100   тепле тло секцій         → аліас --bg-bage
   ```
   ⚠️ Золото `--brand-gold-400` на білому дає контраст ~1.5:1 — як текст не використовувати.
2. **Прочитай поточні стилі блоку повністю** — зрозумій структуру БЕМ і що вже є.
3. **Прочитай розмітку** (PHP/HTML) — які елементи генеруються динамічно
   (CF7-форми, swiper-слайди, WP-меню). Їх класи чіпати ризиковано.
4. **Прочитай JS** блоку — які класи навішує бібліотека (напр. swiper:
   `swiper-slide-thumb-active`, `spaceBetween`), щоб стилізувати реальні стани.
5. Тільки тоді — редизайн.

## 1. Принципи

- **Єдина система карток.** Спільні токени радіуса/тіні/бордера як локальні
  `$`-змінні зверху файлу. Усі картки секції — одна родина.
- **Типографічна ієрархія.** Виділи патерн дрібного заголовка (eyebrow) у `@mixin`
  і застосуй однаково скрізь. Великий заголовок — серіф/акцент, тіло — читабельний sans.
- **Прибери анти-патерни UX.** Найчастіші: `white-space: nowrap` + `text-overflow: ellipsis`
  на динамічному тексті (обрізає контент), `text-align: justify` (рвані проміжки),
  холодні сірі фони замість теплих брендових, фіксовані висоти рядків що ламають перенос.
- **Мікро-взаємодії.** Hover/focus/active стани через наявний `$hover-trans`.
  Focus на інпутах — у бренд-колір. Кнопки — легкий lift + тінь на hover.
- **Простір і ритм.** Збільшуй `gap`/`padding` радше, ніж додавай декор. Менше — краще.
- **Responsive.** Mobile-first через `@include minw(...)`. Сайдбар — фіксована ширина
  + `minmax(0, 1fr)` для контенту (запобігає переповненню grid).

## 2. Типові блоки

### Картка
```scss
padding: 3rem 2.5rem;
background: var(--white);
border: $card-border;
border-radius: $card-radius;
box-shadow: $card-shadow;
```

### Eyebrow-заголовок
```scss
@mixin eyebrow {
    position: relative; display: inline-block;
    color: var(--bg);                 // = --brand-green-700
    font-size: 1.2rem; font-weight: 900;
    letter-spacing: 0.2rem; text-transform: uppercase;
    margin-bottom: 1.6rem; padding-bottom: 1rem;
    &::after { content:''; position:absolute; left:0; bottom:0;
               width:3.5rem; height:0.2rem; background: var(--brand-gold-600); }
}
```

### Чіпи зі списку через кому (PHP)
Розбивай перелік на елементи лише якщо це простий текст, з фолбеком:
```php
if ( $val && strpos($val,'<')===false && strpos($val,',')!==false ):
    $items = array_filter( array_map('trim', explode(',', $val)) );
    // <ul class="...__list"><li>chip</li>...</ul>
else: // <p>{$val}</p>
endif;
```

### Слайдер (swiper) — активна мініатюра
Рамку активного стану став на `::after` **всередині** `overflow:hidden`, а не зовнішнім
`box-shadow` (його обрізає вʼюпорт swiper). Inset-`box-shadow` теж не підійде —
його перекриває `<img>`.
```scss
.thumb::after { content:''; position:absolute; inset:0;
                border:0.2rem solid transparent; border-radius:inherit; }
.swiper-slide-thumb-active .thumb::after { border-color: var(--accent); }
```

## 3. Чого не робити

- Не хардкодити кольори/шрифти — бери з токенів проєкту.
- Не перейменовувати класи, на які зав'язані JS/бібліотеки чи серверна розмітка.
- Не змінювати дані/контент під виглядом стилю.
- Не запускати білд вручну, якщо в проєкті працює автоматичний watch (`npm run dev` = gulp watch)
  — див. [[code-testing]].
- Не правити `build/` — це згенерований вивід Gulp. Тільки `dev/`.

## 4. Фінал

- Поясни рішення коротко в ролі senior UI/UX (що і **чому**, які UX-проблеми усунув).
- За потреби онови `REDESIGN.md` з токенами й ключовими рішеннями.
